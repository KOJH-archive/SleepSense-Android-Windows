# SleepSense Android 야간 보호 앱

갤럭시 S26 Ultra를 우선 검증 대상으로 개발한 Android 12 이상용 첫 개발 버전이다. 완전히 어두운 방에서도 사용할 수 있도록 카메라·마이크를 사용하지 않는다.

현재 기능은 실제 수면 확정이 아니라 **기기 무활동 및 사용자가 선택한 시간에 따른 재생 보호**다. 스마트워치 수면 신호, 호흡 분류, 실제 배터리 절감 검증은 아직 구현·검증하지 않았다. Windows 앱은 이후 단계다.

## 설치와 처음 사용

1. 작업 폴더의 `dist/SleepSense-0.1.0-night-alpha.apk`를 스마트폰으로 옮겨 설치한다. 해당 파일을 여는 앱의 설치 허용이 필요한 경우 Android 설정에서 허용한다.
2. SleepSense에서 `미디어 제어 연결하기`를 누르고 시스템 알림 접근 설정에서 SleepSense를 켠다. 재생 제어를 위한 넓은 권한이므로 설명을 확인한다. 앱은 알림 본문·대화 내용을 처리하거나 저장하지 않는다.
3. `보호 상태 알림 허용`을 눌러 보호 상태와 되돌리기 알림을 허용한다.
4. YouTube, Spotify 등 실제 사용하는 앱에서 재생을 시작하고 SleepSense로 돌아온다.
5. `재생 중 · 정지 가능`으로 표시되는 대상 하나를 고른다. 표시되지 않거나 정지 미지원인 앱은 현재 제어할 수 없다.
6. 처음에는 `2분 기능 확인 · 실제 재생이 멈춰요`로 확인한다. 약 2분 재생 뒤 15초 취소 유예를 거쳐 실제 정지 명령을 보낸다. 이는 개발용 APK에서만 제공한다.
7. 정지 성공 뒤 60초 안에 알림의 `되돌리기`를 누른다. 같은 미디어 세션·같은 항목이 계속 존재하는 경우에만 재생을 요청한다.
8. 정상 동작을 확인하면 `오늘 밤 보호 시작`을 사용한다. 시작 후 처음 30초는 휴대폰을 내려놓고 움직임 센서를 보정한다.

2분 테스트도 사용자가 선택한 앱을 실제로 정지한다. SleepSense가 스스로 테스트 재생이나 일시정지를 시작하지는 않는다.

2분 기능 확인은 되돌리기 결과를 확인하면 회차를 종료한다. 정상 야간 보호에서만 복구 후 cooldown과 재관찰을 적용한다.

## 기본 동작

- 기본 무활동 시간은 45분이다. 휴대폰이 지속적으로 움직이면 다시 시간을 센다.
- 거치대에 놓고 깨어서 시청하거나 음악을 듣는 경우에도 무활동 시간이 지날 수 있다. 이 조건을 원치 않으면 무활동을 끄고 최대 재생시간만 선택한다.
- 최대 재생시간은 기본 꺼짐이며 별도로 선택해야 한다. 선택한 앱이 Playing인 관측 구간에만 합산한다. 일반 움직임으로 상한을 늘리지 않는다.
- 앱·알림의 `계속 재생`은 허용 시간을 새로 시작한다. 자동 종료 전 취소 또는 성공 복구 후 15분 동안 재개입을 쉬며, 두 차례 취소·복구하면 해당 회차를 종료한다.
- 일시정지를 5초 이내 확인하지 못하면 같은 세션에 한 번만 재시도한다. 실패 뒤 토글 키·뮤트·강제 종료를 하지 않는다.
- 성공한 정지를 확인하면 센서를 즉시 해제하고 60초 복구 창이 지나면 감지 서비스를 종료한다.
- 화면 켜짐·단순 뒤척임은 자동 재생 신호가 아니다. 다른 앱의 모든 터치도 감시하지 않는다.
- 앱 재시작·세션 교체·항목 변경·권한 취소 뒤 이전 정지 기록으로 자동 재생하지 않는다.
- 프로그램은 화면을 강제로 잠그지 않으며, 외부 앱의 화면 유지 정책은 보장하지 않는다.
- 보호 회차는 최대 8시간이다. 일정 자동 시작과 스마트워치 연동은 현재 구현하지 않았다.

## 화면 꺼짐과 갤럭시 전원 관리

앱은 화면을 계속 켜 놓는 플래그, 지속 wake lock, 정확한 알람을 사용하지 않는다. 휴대폰이 suspend되거나 제조사 전원 관리가 센서 전달을 멈추면 감지가 늦거나 보류될 수 있다. 이 상황을 수면이나 무활동으로 오인하지 않으며, 5초 넘는 센서 공백 뒤에는 연속 무활동 시간을 처음부터 센다.

최대 재생시간도 OS 스케줄링에 따라 정지 요청이 지연될 수 있다. 현재 버전은 절전 중 정확한 시각의 종료를 보장하지 않는다. S26 Ultra의 실제 OS 버전, 사용 앱, 화면 잠금, Bluetooth 이어폰, 배터리 설정으로 검증해야 한다.

배터리 최적화 예외를 자동 요청하지 않는다. 감지가 자주 중단되면 앱의 `앱 권한과 배터리 설정`에서 상태를 확인할 수 있다. 설정 변경만으로 실행을 보장한다고 표시하지 않는다.

## 개인정보

카메라, 마이크, 인터넷, 접근성, 화면 캡처, Device Admin, 저장소, 건강 데이터 권한을 요청하지 않는다. 런타임 원본 영상·음성·건강 데이터는 수집하지 않는다. 센서 움직임 특징은 메모리에서만 사용한다.

설정과 최근 종료 안내 한 건만 앱 전용 저장소에 보관한다. 최근 기록은 최대 7일 표시하며 직접 삭제할 수 있다. 기록에 콘텐츠 제목·URL·알림 본문·센서 측정값은 포함하지 않는다. 클라우드 백업·기기 간 설정 전송도 제외한다. Android 자체 또는 미디어 앱의 서버 통신은 SleepSense가 통제하는 범위가 아니다.

## 개발과 빌드

Android Studio에서 이 `android` 폴더를 연다. 사용 버전은 Gradle 8.13, AGP 8.13.2, Kotlin 2.2.21, compileSdk/targetSdk 36, minSdk 31이다. JDK 21과 Android SDK platform 36 및 build-tools 35.0.0을 준비한다. 라이브러리는 확인한 버전으로 고정했다.

```powershell
.\gradlew.bat :core:test :app:assembleDebug :app:lintDebug
```

Windows의 일부 Java/Gradle 작업자는 한글 경로에서 실행이 실패할 수 있다. 일반 개발 환경에서는 소스·SDK·Gradle 캐시를 ASCII 경로에 놓는 것을 권장한다. 이 채팅의 빌드는 동일 작업 폴더에 대한 ASCII 경로 링크를 사용하며 소스를 별도로 복제하지 않는다. 사용자별 `local.properties`, 개발 도구, 캐시, debug keystore는 소스 관리에서 제외한다.

현재 서명은 개발용 debug 서명이다. Play 배포용 서명·정책 심사·호환성 검증은 완료되지 않았다. 사용자가 시작하는 감시 FGS는 Android 14 이상에서 `specialUse`를 선언하며, Play 배포에는 해당 용도의 심사를 별도로 통과해야 한다.

## 코드 구조

- `core`: Android에 의존하지 않는 상태기계와 안전성 단위 테스트.
- `app/media`: 사용자가 허용한 NotificationListenerService와 지정 MediaController 제어.
- `app/sensors`: 저속 가속도 수집, 정지 보정, 움직임 지속 시간 검사.
- `app/service`: 야간 foreground 회차, 무음 알림, 명령 확인, 되돌리기, 자원 해제.
- `app/MainActivity.kt`: 야간 어두운 화면, 대상 선택, 시간 설정, 권한 안내.

## 다음 검증

사용자 S26 Ultra에서 YouTube·Netflix·음악 앱별 Pause/Play, 화면 잠금, Bluetooth 이어폰, 센서 공백, 배터리 최적화, 8시간 실행을 검증한다. 성공 앱 조합만 호환 목록에 등록한다. 센서가 추가로 소비한 전력을 포함한 비교 측정이 필요하다.

실제 수면 진입 추정은 지원 웨어러블·착용·지연·로컬 전송 경로가 확인된 뒤 추가한다. 어두운 RGB 영상이나 콘텐츠에 섞인 호흡음을 검증 없이 수면 근거로 사용하지 않는다.
